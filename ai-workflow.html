AI-assisted workflow

AI tools speed up drafting SQL, Python and documentation. The engineer still owns whether the result is right.

Validation checklist for AI-generated SQL and code

  1. Read every line and explain it in plain words before running it.
  2. Run on a small sample in a non-production copy.
  3. Compare row counts and totals with the source or the old query.
  4. Find differing rows with EXCEPT in both directions.
  5. Test edge cases: NULLs, duplicate keys, empty days, time zones.
  6. Compare the execution plan, not only the runtime.
  7. Record what was checked in the change notes, then deploy.

Example: proving a rewrite is correct, not just plausible

An AI-suggested rewrite of a slow daily revenue query must return the same rows as the original.

-- rows in the original but missing from the rewrite
SELECT * FROM (original_query) o
EXCEPT
SELECT * FROM (rewritten_query) r;

-- rows in the rewrite but not in the original
SELECT * FROM (rewritten_query) r
EXCEPT
SELECT * FROM (original_query) o;

-- both must return zero rows; then compare totals
SELECT SUM(revenue), COUNT(*) FROM (rewritten_query) r;

What stays with the engineer

  • Business definitions, such as what counts as an active subscriber.
  • Anything that writes to production data.
  • Sign-off on results that other teams will rely on.
