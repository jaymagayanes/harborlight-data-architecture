A record's journey

  1. Land. A file, API page or event arrives and is stored untouched in S3.
  2. Validate. Schema, completeness and volume checks run. Bad data goes to quarantine.
  3. Stage. Types are fixed and duplicates removed in the warehouse.
  4. Model. Business rules turn it into facts and dimensions, once, in one place.
  5. Serve. Marts feed dashboards, alerts and data feeds that teams rely on.

Design choices

  • Keep raw data untouched. Any table can be rebuilt after a bug fix.
  • Three warehouse layers. Staging cleans, core holds business entities, marts answer one team's questions each.
  • Batch and streaming side by side. Finance gets a correct daily number. Operations gets a view that is minutes old. Both use the same core model.
  • Checks are part of the pipeline. A failed check stops the load and alerts the on-call person.
